# Contributing

## Setup

```bash
git clone https://github.com/jhwohlgemuth/okf-plan-browser.git
cd okf-plan-browser
npm ci
npm run dev        # http://localhost:5173
```

Use Chrome or Edge for the File System Access API. The `gh` CLI and `make` are needed for the GitHub tasks below.

## Make tasks

Run `make help` for the full list.

| Task | What it does |
|---|---|
| `make dev` | Start the Vite dev server |
| `make lint` / `make typecheck` / `make test` | ESLint, `tsc`, Vitest |
| `make audit` | `npm audit` on production dependencies (fails on critical) |
| `make build` | Production web build into `dist/` |
| `make ci` | Everything CI runs, locally |
| `make visual` / `make visual-update` | Run or re-baseline visual regression tests; the update also refreshes README screenshots |
| `make tauri-dev` / `make tauri-build` | Desktop app in dev mode, or local installers |
| `make pages-enable` / `make pages-deploy` / `make pages-url` | GitHub Pages setup, deploy, and URL |
| `make release BUMP=patch\|minor\|major` | Bump the version and watch the desktop release build |
| `make release-view` / `release-download` / `release-delete` | Inspect, download, or remove a release (`TAG=vX.Y.Z`) |
| `make runs` / `watch` / `logs` / `ci-status` | Inspect GitHub Actions runs |

## Tests

- **Unit:** `npm test` (Vitest, in `src/**/*.test.ts`).
- **Visual regression:** `npm run test:visual` (Playwright). Baselines live in `e2e/__screenshots__` and are per platform. Use `PW_CHANNEL=msedge` to run on Edge. Update them with `npm run test:visual:update`.

CI runs the audit, lint, type check, tests and build on every pull request.

## Maintaining the planning skill

This repository is the official home of the planning skill. Edit the canonical instructions in `.agents/skills/planning/SKILL.md` and the relevant references for portfolio maintenance, resumable implementation, drafting, or evidence review. Keep `agents/openai.yaml` consistent with the skill's capabilities.

The Planning Skill page imports these files directly at build time. When adding or removing a skill resource, update the imports and `SKILL_FILES` in `src/pages/PlanningPage.tsx` so the source viewer and downloadable ZIP remain complete. Update the README and site prompts when the user workflow changes. Generated bytecode does not belong in the package.

Run `npm run lint` and `npm run build` for site changes. For validator changes, also run:

```bash
python3 -m unittest discover -s .agents/skills/planning/scripts -p "test_*.py"
```

When changing `.wiki` plans, run `python3 .agents/skills/planning/scripts/validate_wiki.py .`. Keep active plans focused on remaining work and preserve durable evidence before retiring them.

## Deploy to GitHub Pages

One-time setup: run `make pages-enable`, or open **Settings → Pages → Source → GitHub Actions**.

`deploy-pages.yml` runs on every push to `main`. It builds Vite with the correct base path and deploys `dist/`. The base path comes from the repository name. If the site is served from a custom domain, it appears under `/okf-plan-browser/` there. Run it by hand with `make pages-deploy`.

## Desktop app (Tauri)

Install Rust from <https://rustup.rs>, then:

```bash
npm run tauri:dev     # dev mode
npm run tauri:build   # production binary
```

## Releasing

```bash
make release BUMP=patch   # or minor / major
```

For a specific version, prepare and commit the version files, then publish the tag:

```bash
make release-prepare VERSION=0.0.1
git add package.json package-lock.json src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/Cargo.lock
git commit -m "Release v0.0.1"
make release-publish VERSION=0.0.1
```

`release-publish` requires a clean tree, pushes the commit, and then pushes the tag to start the Release workflow. Inspect it with `make release-watch` and `make release-view TAG=v0.0.1`.
If a draft release fails before publication, commit the fix and retry the same unpublished tag with `make release-retry-draft VERSION=0.0.1 EXPECTED_TAG_SHA=<remote-tag-commit>`. The lease refuses to move a tag that changed remotely.

This runs the **Version Bump** workflow, which updates `package.json` and `tauri.conf.json`, commits, tags `vX.Y.Z`, and starts the **Release** workflow. That workflow attaches Apple Silicon and Intel macOS DMGs, a Windows MSI, and Linux Debian and AppImage packages to a draft GitHub release. It checks that all five assets are present, attaches `SHA256SUMS`, and only then publishes the release. Intel macOS builds are provided as artifacts but are not a supported desktop-ingest target.

- Release builds are unsigned, so operating systems warn on first launch.
- To release an existing tag, run `make release-run TAG=vX.Y.Z`. Pushing a `v*` tag also starts the workflow.
- Check the result with `make release-view TAG=vX.Y.Z`.

## CI and security

- All third-party actions are pinned to commit SHAs. Dependabot keeps them current.
- Workflows default to read-only permissions; write access is granted per job.
- The app ships a strict Content Security Policy, set in `src-tauri/tauri.conf.json` and injected into the web build by `vite.config.ts`. Web forge destinations come from `OKF_GITLAB_HOSTS`; never restore a blanket `https:` source.
- `npm run dev` always supports `gitlab.com` and `code.ornl.gov`, and proxies additional hosts listed in `OKF_GITLAB_HOSTS`. Set a comma-separated list before starting Vite when testing another GitLab host.
- Production Pages/custom-domain configuration must redirect HTTP to HTTPS before token entry is enabled. Verify the effective URL and enable HSTS after HTTPS works.
- Browser tokens are session-only. Desktop tokens are stored by the Rust backend in the operating system credential store and are attached only to exact-host requests.
